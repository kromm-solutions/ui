Kromm UI is a registry of components compatible with shadcn, plus the
documentation site you are reading. It is not a product app: the published
artifact is the registry (`public/r/`) and these docs.

Every component ships on three headless bases - `base` (Base UI),
`aria` (React Aria) and `radix` (Radix) - so you choose the primitive layer
that fits your stack without changing styling or API.

## What You Get

- Three bases, always - a component change lands on all three bases, unless a
  single base is explicitly accepted.
- shadcn compatible - the registry works with the standard CLI.
- Copy-and-own - installing a component copies readable code into your
  project; there is no runtime dependency to fight.
- Documentation site - Fumadocs (MDX), command palette (⌘K), sitemap, OG
  images, prev/next navigation.
- Agent ready - `llms.txt`, `llms-full.txt`, API catalog routes and agent
  skill discovery endpoints.
- Web audio feedback - interaction sounds powered by `@web-kits/audio`.
- Web haptics - optional haptic feedback for supported devices via
  `web-haptics`.
- Motion animations - `motion` for animated UI states and transitions.
- Animated icons - reusable animated icons for buttons, sharing and
  navigation.
- View transitions - Next.js view transitions for smoother page changes.

## Tech Stack

- Fumadocs (MDX)

## How It Works

1. Source components live in
   `registry-kromm-ui/bases/<base>/kromm-ui/<component>/` together with their
   `registry.ts`.
2. `pnpm registry:all` regenerates `_meta/` and builds `public/r/`. Never edit
   those by hand.
3. Users install a copy of each component into their own project:

```bash
npx shadcn@latest add https://your-site.com/r/<component>.json
```

## FAQ

### Why copy/paste instead of npm packages?

The shadcn philosophy gives you ownership of the code. You can customize
components to your exact needs without fighting library constraints.

### Why three bases?

Headless libraries solve the same accessibility problems with different APIs
and trade-offs. Kromm UI keeps the styled layer constant, so moving from
Radix to Base UI or React Aria is a drop-in change, not a redesign.

### Can I publish my own components?

Yes. Add them under `registry-kromm-ui/bases/<base>/kromm-ui/`, export them
in the corresponding `registry.ts`, run `pnpm registry:all`, and deploy - the
docs and registry files propagate automatically.
