# AGENTS.md

Guidance for AI coding agents working in this repository. Human-facing rationale lives in [CONTRIBUTING.md](./CONTRIBUTING.md) — this file is the operational entry point.

## What this repo is

`kromm ui` — a shadcn-compatible component registry: headless UI primitives across **Base UI**, **Radix UI** and **React Aria**, build-time visual styles, and agent-facing tooling (`/llms.txt`, `/.well-known/agent-skills`, API catalog). Everything under `registry/` and `registry-kromm-ui/` **ships verbatim to consumers** through the shadcn CLI — treat it as published API, not app code.

## Setup

```bash
pnpm install   # Node 22+, pnpm 10.28.x (pinned in package.json)
pnpm dev
```

## Gates — all must pass before committing

| Command               | Purpose                            |
| --------------------- | ---------------------------------- |
| `pnpm typecheck`      | `tsc --noEmit`, zero errors        |
| `pnpm check`          | ultracite (Biome) app-code style   |
| `pnpm lint:ds:errors` | design-system lint, errors only    |
| `pnpm registry:all`   | registry metadata → build → verify |

If a lint diagnostic points at a rule, fix the code — never suppress the rule.

## Conventions that bite agents

- **Commit messages:** [Conventional Commits](https://www.conventionalcommits.org/). They drive release-please versioning, so the type prefix must be accurate (`feat` vs `fix` vs `chore` …).
- **Branches:** day-to-day work on `development` (or `feature/*` off it). Never commit directly to `main`.
- **Registry items:** declare in each base's `registry.ts`; bare `registryDependencies` (`"button"`) are rewritten to `@kromm/button` at build time — do not hardcode the scope.
- **Style tokens:** per-style Tailwind tokens (`style-vega:… style-nova:…`) must cover every style in `kromm/registry/resolve-styles.ts`; the verifier hard-fails on unresolved residue.
- **Never edit by hand:** `registry-kromm-ui/_meta/` (regenerated by `pnpm registry:metadata`) and `public/r/` (regenerated by `pnpm registry:build`).
- **New registry items** must include `meta.json` fields `bestFor`, `whenNotToUse`, `agentNotes` so future agents pick components correctly.

## Validation of agent work

Agent output goes through the same CI gates as human output, plus a human visual review before merge. The distribution channel itself is verified end-to-end on every release by `scripts/smoke-distribution.mjs` and the `install-e2e` job in `.github/workflows/smoke.yml`.
